# Deploying Nimiq Pulse

| Part | Platform | Status | URL |
| --- | --- | --- | --- |
| Frontend | Vercel | **live** | https://nimiq-pulse.vercel.app |
| Backend | Render (free) | needs one click-through | *pending* |

Both free. The split exists because the two halves have incompatible needs: the
frontend is static files, and the backend must be a **long-running process** —
the embedded Nimiq light client takes ~40 s to reach consensus and holds open
peer connections, so serverless cannot host it.

---

## 1. Backend on Render — 5 minutes

The repo already contains [`render.yaml`](../render.yaml), so Render configures
itself. You only supply two values it refuses to read from a repo.

1. Go to **[dashboard.render.com](https://dashboard.render.com)** and sign in with GitHub.
   No credit card needed for the free plan.
2. **New → Blueprint**.
3. Pick the **`Kachi333/nimiq-pulse`** repository. Render finds `render.yaml`
   and proposes a service named `pulse-api`.
4. It prompts for the two secrets:

   | Key | Value |
   | --- | --- |
   | `TIP_JAR_ADDRESS` | An address **you control** — Nimiq Pay → Receive → copy |
   | `CORS_ORIGINS` | `https://nimiq-pulse.vercel.app` — exact, **no trailing slash** |

   `JWT_SECRET` is generated by Render automatically. Everything else comes from
   the blueprint.
5. **Apply**. First build takes 2–4 minutes.

You will get a URL like `https://pulse-api-xxxx.onrender.com`. Confirm it:

```sh
curl https://pulse-api-xxxx.onrender.com/health
```

Wait for `"chain":{"ready":true}` — about 40 s after the container starts. Until
then the API answers but has no chain data.

## 2. Point the frontend at it

The frontend cannot reach any API until this is set. Its fallback is
`http://<host>:8787`, which on an HTTPS page is both wrong and blocked as mixed
content.

```sh
cd nimiq-pulse
vercel env add VITE_API_BASE production      # paste the Render URL, no trailing slash
vercel env add VITE_TIP_JAR_ADDRESS production   # same address as TIP_JAR_ADDRESS
vercel deploy --prod --yes                   # rebuild with the values baked in
```

`VITE_*` values are inlined at **build** time, so setting them without
redeploying changes nothing.

---

## 3. Keep it awake

Render free instances sleep after 15 minutes idle. Waking costs 30–60 s of cold
start plus ~40 s to re-reach consensus — over a minute for a judge clicking a
cold link.

[`.github/workflows/keep-warm.yml`](../.github/workflows/keep-warm.yml) pings
`/health` every 10 minutes. Point it at the deployed API:

```sh
gh variable set API_URL --body "https://pulse-api-xxxx.onrender.com"
gh workflow run keep-warm      # verify it works now
```

The free allowance is 750 instance-hours per month against a ~730-hour month, so
one always-on service stays inside it.

## 4. Verify end to end

```sh
curl https://pulse-api-xxxx.onrender.com/health          # chain.ready true
curl -sI https://nimiq-pulse.vercel.app | head -1        # 200

# CORS must name the frontend exactly
curl -si -X OPTIONS https://pulse-api-xxxx.onrender.com/profile \
  -H 'Origin: https://nimiq-pulse.vercel.app' \
  -H 'Access-Control-Request-Method: GET' | grep -i access-control-allow-origin
```

Then on a phone:

```
nimiqpay://miniapp?url=https://nimiq-pulse.vercel.app
```

## 5. Things that will bite

**CORS is an exact string match.** `https://nimiq-pulse.vercel.app/` with a
trailing slash does not match. Symptom: the app loads perfectly and every screen
is empty, with no visible error. Check this first.

**Vercel preview deployments get different URLs** and are not in the allowlist,
so only the production domain works. Test the real link, not a preview.

**The database is ephemeral on Render free.** Every deploy wipes it, so the
server re-seeds the registry from `registry.seed.json` on boot and the indexer
rebuilds from chain. Nothing is permanently lost, but XP and interactions take a
few minutes to reappear. Anything added with `registry:add` locally must be in
`registry.seed.json` and committed to survive.

**Set `SEED_INCLUDE_DEMO=false`** in Render once you have real Mini App
addresses, or the demo entry keeps coming back on every restart.

**The origin is effectively permanent.** Nimiq Pay's device identifier is scoped
to the origin, so changing domains later resets every device-based abuse limit.
Settle on `nimiq-pulse.vercel.app` now, or move to a custom domain before
sharing the link widely.
